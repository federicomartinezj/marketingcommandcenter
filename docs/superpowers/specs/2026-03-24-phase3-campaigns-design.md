# Phase 3: Campañas Completas — Design Spec

**Date:** 2026-03-24
**Status:** Draft
**Goal:** Enable full campaign creation where the marketing director describes a campaign in natural language and the system generates a complete multi-channel funnel with A/B variants, organized by embudo stage.

---

## Context

Lavanti's Marketing Command Center currently supports individual content creation (blog posts, social posts, emails) through a linear agent pipeline. Phase 3 elevates this to full campaign orchestration — a single brief produces a coordinated set of content pieces across multiple channels, tied together by a unifying concept and funnel strategy.

### Example Campaign

> **Brief:** "Los jefes de mantenimiento de hoteles están cansados de reparar equipos viejos y buscar repuestos de afán. Quiero una campaña para OPL dirigida a ellos."
>
> **Result:** Awareness (WhatsApp piece + Facebook Ad) → Nurture (email sequence + blog) → Conversion (landing page). All tied to concept "Deja de apagar incendios" with 3 copy variants per piece.

---

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Wizard flow | Hybrid: free brief → auto-generated plan → review → execute | Natural input, structured output, director has control before execution |
| Orchestration | Phased pipeline: Strategy (sequential) → Generation (parallel by channel) → Review | Coherent strategy + fast parallel execution |
| A/B testing | Essential — 2-3 variants per piece from the start | Director always gets options, not single decisions |
| UX Strategist role | Strategist — defines funnel and structures before Copywriter writes | Shapes the campaign architecture |
| SEO Specialist role | Optimizer — refines blog/landing content with keywords after generation | Polishes SEO-relevant content only |
| Output | Downloadable campaign package (ZIP) organized by funnel stage → channel | Director copies content to platforms manually |

## Data Model

### Relationship to Existing Types

The existing `CampaignBrief` interface is **replaced** by the `Campaign` interface below. The existing `ExecutionPlan` and `ExecutionStep` are reused for Phase 1 (strategy) execution tracking. `ContentPiece` is **not** reused for campaign channels — campaign content lives entirely within the `Campaign` object via `ChannelPlan`. This avoids dual storage and keeps campaigns self-contained. The content list view will query both the existing content store and campaigns to show a unified pipeline view.

### New ContentType Values

Extend the existing `ContentType` union with campaign-specific types:

```typescript
// Added to existing ContentType
type ContentType =
  | "blog-post" | "linkedin-post" | "instagram-post"
  | "email" | "email-sequence" | "landing-page" | "social-card"
  | "whatsapp"                    // NEW: WhatsApp shareable piece
  | "facebook-ad"                 // NEW: Facebook/Instagram ad copy
```

### Campaign

```typescript
interface Campaign {
  id: string
  name: string                      // "Campaña Jefes Mantenimiento - OPL"
  brief: string                     // Free text from director
  line: BusinessLine                // OPL, AAS, MH, Volta
  audience: string                  // "Jefes de mantenimiento hotelero" (matches existing CampaignBrief field name)
  objective: string                 // Campaign goal (reused from existing CampaignBrief)
  concept: string                   // Unifying concept generated by UX Strategist
  funnel: FunnelStage[]             // Funnel defined by UX Strategist
  channels: ChannelPlan[]           // Channels with their pieces
  status: CampaignStatus
  createdAt: string
  updatedAt: string
}

type CampaignStatus = "draft" | "planning" | "planned" | "generating" | "review" | "approved" | "exported"
```

### Funnel Stage

```typescript
interface FunnelStage {
  stage: "awareness" | "interest" | "nurture" | "conversion"
  description: string               // "Pieza WhatsApp + pauta Facebook"
  channels: ContentType[]           // ["whatsapp", "facebook-ad"] — uses ContentType, not free strings
}
```

### Channel Plan

```typescript
interface ChannelPlan {
  id: string                        // UUID — unique identifier for API routing
  channel: ContentType              // Uses existing ContentType union
  funnelStage: "awareness" | "interest" | "nurture" | "conversion"
  variants: ContentVariant[]        // 2-3 copy variants
  designHtml?: string
  seoOptimization?: SEOResult
  brandReview?: BrandReview         // Reuses existing BrandReview interface
  status: "pending" | "generating" | "ready" | "error" | "approved"
}
```

### Content Variant

```typescript
interface ContentVariant {
  id: string
  label: "A" | "B" | "C"
  content: string                   // Generated copy
  selected: boolean                 // Whether director chose this variant
}
```

### SEO Result

```typescript
interface SEOResult {
  keywords: string[]
  suggestions: string[]
  score: number
  metaDescription: string
  optimizedTitle: string
}
```

### Campaign Status Flow

```
draft → planning (UX Strategist working) → planned (director reviewing plan)
→ generating (content in parallel) → review (Brand Guardian)
→ approved (director approved) → exported (package downloaded)
```

## New Agents

### UX Strategist

- **When:** Phase 1 of pipeline, after Orchestrator analyzes brief
- **Input:** Analyzed brief + business line + target audience
- **Output format:** JSON parsed into Campaign fields:
  ```typescript
  {
    concept: string,           // Unifying creative concept
    funnel: FunnelStage[],     // Parsed into Campaign.funnel
    landingStructure?: {       // Only if landing-page is a channel
      sections: ("hero" | "pain-points" | "benefits" | "social-proof" | "cta")[]
      sectionBriefs: Record<string, string>  // Brief per section for Copywriter
    }
  }
  ```
- **Brand context:** Loaded dynamically via `loadAllBrandContext(line)` like existing agents
- **Parsing:** The orchestrator parses the JSON from `AgentOutput.content`. If parsing fails, campaign status stays `draft` and the error is surfaced to the UI.

### SEO Specialist

- **When:** Phase 2 of pipeline, in parallel — only for `blog-post` and `landing-page` channel types
- **Input:** Copy already generated by Copywriter + business line
- **Output format:** JSON parsed into `SEOResult`:
  ```typescript
  {
    keywords: string[],
    suggestions: string[],    // Actionable optimization suggestions
    score: number,            // 0-100 SEO readiness score
    metaDescription: string,
    optimizedTitle: string
  }
  ```
- **Does NOT participate in:** WhatsApp, emails, social posts

### Changes to Existing Agents

- **Copywriter:** Extended to generate 3 variants per piece instead of 1. Receives UX Strategist's concept and funnel as additional context.
- **Social Media Manager:** Handles WhatsApp and Facebook Ad copy (already manages platform-specific content).
- **Designer:** No changes — continues generating HTML/CSS visual assets.
- **Brand Guardian:** No changes — reviews each piece individually in Phase 3.

## Orchestration Architecture

### Phased Pipeline

**Phase 1 — Strategy (sequential):**
1. Orchestrator analyzes brief, identifies business line, target, and candidate channels
2. UX Strategist receives analysis, generates unifying concept, defines funnel stages, structures landing page

**Phase 2 — Generation (parallel by channel):**
Each channel runs independently as a mini-pipeline using `Promise.allSettled()`:
- **WhatsApp/Facebook Ad:** Social Media Manager (×3 variants) + Designer
- **Email sequence:** Copywriter (×3 variants per email) + Designer
- **Blog:** Copywriter (×3 variants) + SEO Specialist
- **Landing page:** Copywriter (×3 variants) + Designer + SEO Specialist

All channels receive the UX Strategist's concept and funnel as shared context.

**Error handling:** `Promise.allSettled` allows each channel to succeed or fail independently. Failed channels get `status: "error"` on their `ChannelPlan` and can be retried individually via `POST /api/campaigns/:id/channels/:channelId/regenerate`. Successful channels proceed normally.

**Phase 3 — Review (sequential per piece):**
Brand Guardian reviews each channel's selected variant (or all variants if none selected yet).

### Callback Pattern

New `CampaignCallbacks` interface (does not extend existing `OrchestratorCallbacks` — different scope):

```typescript
interface CampaignCallbacks {
  onPhaseStarted(phase: 1 | 2 | 3): void
  onChannelStarted(channelId: string, channel: ContentType): void
  onChannelCompleted(channelId: string, channel: ContentType): void
  onChannelFailed(channelId: string, channel: ContentType, error: string): void
  onCampaignCompleted(campaign: Campaign): void
}
```

The existing `OrchestratorCallbacks` (`onPlanCreated`, `onStepStarted`, `onStepCompleted`) continue to be used within each channel's internal mini-pipeline.

## API Routes

```
POST   /api/campaigns                              # Create campaign (brief, line, target)
GET    /api/campaigns                               # List campaigns (filter by line, status)
GET    /api/campaigns/:id                           # Full detail with plan and pieces
PUT    /api/campaigns/:id/plan                      # Approve/modify plan (add/remove channels)
POST   /api/campaigns/:id/generate                  # Trigger parallel generation
PUT    /api/campaigns/:id/channels/:channelId/select  # Select winning variant (channelId = ChannelPlan.id)
POST   /api/campaigns/:id/channels/:channelId/regenerate  # Retry failed channel
PUT    /api/campaigns/:id/approve                   # Approve complete campaign
GET    /api/campaigns/:id/export                    # Download ZIP package
```

### Flow

1. `POST /campaigns` → Creates campaign with status `draft`, returns id immediately
2. `POST /campaigns/:id/analyze` → Triggers Phase 1: Orchestrator + UX Strategist (async via callbacks). Status moves `draft` → `planning` → `planned`. This is a long-running request (~10-20s for two Claude calls), so the response streams progress via SSE or returns immediately with polling via `GET /campaigns/:id`.
3. `PUT /campaigns/:id/plan` → Director adjusts channels → status stays `planned`
4. `POST /campaigns/:id/generate` → Phase 2 parallel: per channel launches Copywriter (×3 variants) + Designer/SEO as needed → callbacks send progress → status `generating` → `review`
5. `PUT /campaigns/:id/channels/:channelId/select` → Selects winning variant per channel
6. `POST /campaigns/:id/channels/:channelId/regenerate` → Retries a failed channel
7. `PUT /campaigns/:id/approve` → Marks entire campaign as approved
8. `GET /campaigns/:id/export` → Generates ZIP in memory and returns it

### Storage

In-memory Map (consistent with current MVP). Replaceable with PostgreSQL without route changes.

## Campaign Wizard UI

### Screen 1 — Brief

- Large text field for free-form campaign description
- Business line selector (OPL/AAS/MH/Volta)
- Target audience field
- "Analizar Brief" button → triggers Phase 1

### Screen 2 — Campaign Plan

- Shows generated unifying concept
- Funnel diagram with stages
- List of channels/pieces to be generated per stage
- Director can add/remove channels before approving
- "Aprobar Plan y Generar" button → triggers Phase 2

### Screen 3 — Live Generation

- Per-channel progress view using existing callback pattern
- Each channel shows: status (generating/ready), agents involved
- Preview available as each channel completes
- Auto-advances to review when all channels finish

### Screen 4 — Review & Selection

- Per channel: view 2-3 variants side by side, select winner
- Brand review score per piece
- Regenerate option for pieces that failed Brand Guardian
- "Aprobar Campaña" button (enabled when all channels have selection)
- "Exportar Paquete" button → downloads ZIP

## Content Pipeline States

The existing `ContentStatus` type (`draft | in-review | approved | rejected | published`) is unchanged. The content list view maps these to Spanish labels:

```
draft → "Borrador"
in-review → "En Revisión"
approved → "Aprobado"
rejected → "Rechazado"
published → "Publicado"
```

Campaign channel pieces use their own `ChannelPlan.status` field (`pending | generating | ready | approved`) which maps to the campaign lifecycle, not the content pipeline. The content list view will show both individual content and campaign channels in a unified list, with campaign pieces grouped under their campaign name.
