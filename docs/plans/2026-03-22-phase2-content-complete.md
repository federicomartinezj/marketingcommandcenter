# Phase 2: Contenido Completo — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Extend the MVP with Designer agent (HTML/React social cards, email templates), Social Media Manager agent, editorial calendar, and rich content preview. Enable the full "create social media post" flow end-to-end.

**Architecture:** New agents follow the same BaseAgent pattern from Phase 1. The Designer generates React/HTML components for visual assets. The Social Media Manager plans and adapts content per platform. The Calendar is a frontend view showing planned content by date/channel. Email templates are pre-built per business line.

**Tech Stack:** Same as Phase 1 + react-markdown (for rich preview), date-fns (for calendar).

## Task 1: Designer Agent

**Files:**
- Create: `backend/src/agents/designer.ts`
- Create: `backend/src/agents/designer.test.ts`

**Step 1: Create Designer agent**

The Designer generates visual specifications and HTML/CSS code for social media cards, email templates, and landing pages. Its system prompt must enforce:

- Correct palette per business line (CRITICAL: MH uses #1DB5DE + #C2D219, NO Coral)
- Manrope font only
- Social card specs: 1200x628 LinkedIn, 1080x1080 Instagram
- Email template structure per line
- Near Black backgrounds for OPL social cards
- Clean/light backgrounds for AAS
- MH Blue vibrant backgrounds for Multihousing

The agent receives a content brief and returns HTML/CSS code that can be rendered as a preview.

**Step 2: Test**

Unit test verifying role and that system prompt contains palette rules.

## Task 9: Editorial Calendar — Backend

**Files:**
- Create: `backend/src/routes/calendar.ts`
- Modify: `backend/src/index.ts`

**Step 1: Create calendar routes**

```
POST /api/calendar — schedule a content piece (date, channel, line, contentId?)
GET /api/calendar?month=YYYY-MM — get all scheduled items for a month
PUT /api/calendar/:id — update schedule
DELETE /api/calendar/:id — remove from calendar
```

In-memory store for MVP. Each calendar item has: id, date, channel (linkedin/instagram/facebook/blog/email), line, title, status (planned/created/published), contentId (optional link to generated content).

**Step 2: Register routes and commit**
